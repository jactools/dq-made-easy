# Kong Bootstrap — SSL Verification, Route Paths, and SSO Session Resolution

**Date**: 2026-08-10  
**Status**: Complete

## Objective and scope

Fix the `dq-job-kong-bootstrap` job so it completes successfully with strict TLS verification and the UI login redirect flow works end-to-end through Kong.

## Problems diagnosed

1. **`http_ok()` always returned false** — The readiness check parsed the raw JSON response body for HTTP status codes instead of using `curl -w '%{http_code}'`. The Kong Admin API returned valid JSON on 200 OK, so `http_ok` never matched and the job timed out after 60 s.

2. **Kong route paths missing `/api` prefix** — Existing Kong routes used `/admin/v1/*` but the UI calls `/api/admin/v1/*`. The `create_route()` function only created routes if they didn't already exist, so it never updated stale paths from previous runs.

3. **Keycloak admin password mismatch** — The `keycloak-admin` K8s Secret held `replace-me` but the database had a different password (or no credential). The bootstrap job's Keycloak admin token call failed with `invalid_grant`.

4. **SSO env vars missing from kong-bootstrap job** — The `APP_CONFIG_INTERNAL_URL` requires auth, so `ssoEnabled`/`ssoIssuer` were never read from the database. Without explicit env vars, the script aborted with "SSO disabled or missing issuer".

5. **`TRUST_PROXY_AUTH` not set on the API** — The FastAPI auth middleware falls back to session-based auth when `TRUST_PROXY_AUTH` is false. Kong validates the JWT and sets `x-consumer-custom-id`, but without `TRUST_PROXY_AUTH=true` the API still tried to look up a session and returned "Session not found".

## Results

| Area | Before | After |
| --- | --- | --- |
| Kong Admin readiness | `http_ok` parsed JSON body for HTTP codes → always false | Uses `curl -w '\n%{http_code}'` → extracts real status code |
| Keycloak readiness | Same broken `http_ok` for Keycloak well-known endpoint | Same fix applied |
| Route path drift | `create_route` only created, never updated existing routes | `create_route` now PATCHes routes when paths change |
| Admin routes | `/admin/v1/*` (missing `/api` prefix) | `/api/admin/v1/*` (matches UI calls) |
| SSO config | Relied on protected app-config API → aborted | `SSO_ENABLED` + `SSO_PUBLIC_ISSUER_URL` explicit env vars |
| API trust mode | `TRUST_PROXY_AUTH=false` → session lookup failed | `TRUST_PROXY_AUTH=true` in `dq-common-config` → Kong JWT trusted |
| Keycloak admin password | `replace-me` placeholder → login failed | Random password generated by `generate_secrets.sh` |
